# 已知问题与实际测试结果

> 3.0.1 发布检查（2026-10-13）：前端类型检查和构建通过；Windows 便携包 `--self-test` 退出码为 0；后端回归 92 项通过。本版更新首页课程看板、今日时间线、周课表与圆角应用图标，并修复较深数据目录下多段录音路径过长的问题。本次没有使用真实课堂录音或本地模型权重验收识别质量。下方 GPU/真实模型加载记录来自 2026-09-11 的旧环境，不代表当前干净机器状态。

## 当前结论

- 语音识别只走本地 `Qwen3-ASR-0.6B`；默认自动选择可用 GPU，不可用时回退 CPU。
- 文字整理只走本地 `Qwen3-4B (Q5_K_M)` + llama.cpp sidecar。
- 设置页已收成两张模型卡和一键准备；启动时不再探测可选外部服务，打开设置更快。
- 长录音按可分析小段处理，证据引用有长度上限；音频播放支持 HTTP Range。

## 已验证

- 前端 `npm run typecheck`、`npm run build`：通过。
- 当前后端回归测试：`92 passed`（2026-10-13；未运行需要真实模型与音频的 `tests/e2e_real.py`）。
- 最终打包程序：`/api/settings` 约 147ms，只返回 1 个 Qwen 语音模型和 1 个 Qwen 文字模型。
- Qwen3-ASR-0.6B 实际加载：`device=cuda`，通过。
- Qwen3-4B 实际最小整理：通过。
- 长录音 Range 请求：返回 `206`、`Content-Range`、`Accept-Ranges: bytes`。
- 程序和侧栏 logo：已打包并可从前端资源加载。
- 旧课堂结果的中文展示保护：卡片不会直接显示英文整理内容；优先使用对应的中文转写稿，缺失时显示中文提示。

## 仍需用户确认

1. 用自己的短课堂录音跑一遍“上传 → 转写 → 整理”，重点检查专业词和中文展示质量。
2. 用桌面快捷方式走一遍新建课程、上传录音、查看重点和勾选完成；本轮未使用真实课堂录音做验收。
3. 在没有开发环境的 Windows 机器上首次启动时，确认 WebView2 和模型下载提示。

桌面视觉自动验收本轮未完成：本机 CUA 环境返回“找不到指定路径”，因此只报告可复现的 API、构建和模型加载结果。

## 设计边界

- 同时只处理一个活动任务，避免长录音互相抢占。
- 事项完成状态由用户手动确认；低置信或无法关联原文的事项不会冒充确定通知。
- 原始英文转写保留，中文展示单独生成，不覆盖原文。
- Windows DPAPI 密钥绑定当前用户和设备，换机后需要重新填写。
