# 开发者构建说明

面向需要在本机构建、调试或二次开发「课堂助手」的开发者。

---

## 一、环境要求

| 项 | 版本 / 说明 |
|----|------|
| Python | 3.12（Qwen3-ASR 运行环境使用此版本，应用已用 Python 3.12 打包验证） |
| Node.js | 20+（含 npm） |
| 操作系统 | Windows 10 / 11（GUI 依赖 WebView2；`--no-gui` 模式可跨平台跑后端） |
| GPU（可选） | NVIDIA 显卡 + 可用的 PyTorch CUDA；Qwen3-ASR 会自动用 GPU，初始化失败则自动改用 CPU。 |

---

## 二、后端构建与运行

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

# 开发模式：仅后端（无 GUI），终端打印本地地址，例如 http://127.0.0.1:54321
python src/main.py --no-gui

# 完整 GUI 模式
python src/main.py
```

> `src/main.py` 是应用入口。后端在 `127.0.0.1` 随机端口启动，GUI 通过 pywebview 同源加载 `frontend/dist`。

### 依赖说明

`requirements.txt` 中**不包含** `llama-cpp-python`：默认方案是「下载 `llama.cpp` 官方 Windows 服务端 `llama-server.exe` + Qwen3-4B GGUF」，无需 Python 绑定。
若你坚持用 Python 绑定方式，可另行安装（需 CUDA 预编译轮子，3.13 无官方预编译）：
```
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
```

## 三、前端构建

```bash
cd frontend
npm install
npm run build      # 产物输出到 frontend/dist/
```

构建产物 `dist/` 会被后端同源直接托管（无需单独起前端 dev server）。
开发期也可 `npm run dev` 单独起 Vite（默认 5173 端口），再让后端 API 指向它做联调。

---

## 四、一键打包为 Windows exe

```bash
# 直接双击 build_exe.bat（会自管 venv、装依赖、构建前端；输出在系统临时目录）
build_exe.bat

# 或手动：
pip install pyinstaller
pyinstaller build_exe.spec --noconfirm --clean --distpath C:\Temp\ca-dist --workpath C:\Temp\ca-work
```

产物：所选输出目录下的 `ClassroomAssistant\ClassroomAssistant.exe`（单文件夹形态，`console=False`）。构建不会清理项目已有的 `build/` 与 `dist/`。

### 打包要点（已在 `build_exe.spec` 内处理）

- 入口 `src/main.py`；`pathex` 含 `src` 以保证 `from backend import ...` 可解析。
- `frontend/dist` 以相对路径 `frontend/dist` 随包携带，与 `api._resolve_dist_dir()` 的查找逻辑对齐（exe 同级目录 / 单文件 MEIPASS 解压根均覆盖）。
- `pywebview` 走 Windows 默认 `edgechromium`（WebView2）平台；spec 用 `collect_submodules` / `collect_data_files` 把全部平台模块与本地资源打包，避免运行期缺模块。
- 排除 `tkinter / matplotlib / PyQt* / PySide*` 等无关 GUI 框架以减小体积。
- 若需图标：放 `课堂助手.ico` 并在 spec 的 `EXE(...)` 里设 `icon="课堂助手.ico"`。

> 注意：Qwen3-ASR 在独立本地 Python 环境运行，GUI 打包产物不再重复携带 PyTorch/CUDA。

## 五、运行测试

```bash
# 自动化测试（无需模型；需先安装 pytest）
python -m pytest tests -q --ignore=tests/e2e_real.py
```

`tests/e2e_real.py` 是需要本地模型和测试音频的手动验收；请只使用有权处理的测试音频，不要把个人课堂录音放入公开仓库。

> **测试隔离**：`tests/conftest.py` 会把 `LOCALAPPDATA` 与 `APPDATA` 一起重定向到临时目录。
> 注意 Windows 上 `paths._appdata()` **优先读 `LOCALAPPDATA`**，只设 `APPDATA` 是无效的，
> 会导致测试直接读写（并删库重建）你的真实数据目录 —— 已由 conftest 里的守卫测试锁死。

测试说明见《已知问题与实际测试结果》。

## 六、关键配置项

- **数据目录**：默认 `%LOCALAPPDATA%/ClassroomAssistant`（Windows 上优先用 `LOCALAPPDATA`，不是 `APPDATA`/Roaming），可在设置页改到其它盘；真实位置记在 `%LOCALAPPDATA%/ClassroomAssistant/app_root.json`。
- **日志级别**：环境变量 `CA_LOG_LEVEL=DEBUG`（默认 INFO）。
- **API 端口**：随机，仅 `127.0.0.1`；如需固定端口改 `src/main.py` 的 `make_server("127.0.0.1", 0)`。

---

## 七、模型相关实现位置（便于二次开发）

- 模型清单（id / 地址 / 大小 / 默认项）：`src/backend/ai/manifest.py`
- 下载与 sidecar 生命周期：`src/backend/ai/llm_provider.py`
- 语音识别：`src/backend/ai/whisper_worker.py`（含 `cuda_runtime_ready()` 与 `resolve_device()`，处理 PyInstaller 打包后缺 cublas DLL 的兼容；运行时 GPU 失败自动回退 CPU）。
- 分析提示词：`src/backend/ai/prompts.py`
- 输出校验/归一化：`src/backend/schemas.py`；去重合并：`src/backend/important.py`
- 更换默认模型：改 `manifest.py` 中的 `is_default` 即可，业务代码无需改动。
